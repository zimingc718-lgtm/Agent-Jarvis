**已确定的方案要点**（第 6 条用户拍板 + 第 7 条确认「按这个来」）：

- 首页展示屏由标题视图改为**知识看板**，分上下两区：上区行业跟踪，下区知识库总览。
- 跟踪对象合并为**三类实体**：友商、规则与准入方（标准与监管接入机构合一，因为并网标准就是 TSO/DSO 所发）、客户。
- 三类状态模型不同：友商是变化检测；规则与准入方是下一个日期 + 在跟踪的规则数 + 可选的容量与队列；客户是容量 + 其发布的商业白皮书与技术准入要求（**不涉及项目交付，故不做健康分**）。
- 每张卡片另有**采集健康度**指示，与内容变化分开显示（区分「对方没动静」与「我们的采集坏了」）。
- **不做**「临近截止」汇总条（用户第 6 条明确去掉）；截止日期退回各自卡片。
- **知识库用同一套实体索引**：实体为主分类、文档类型为次分类；需保留「无归属」桶。

**第 8–9 条补充确定**：

- 首页**保留现有标题视图并加科幻动画**；看板不是首页，是**工作态**。切入规则：本次会话首次加载播动画，3 秒为上限，任一输入即刻切入。
- 本系统**当前仅作信息收集与固化**，存本地；上层对话 Agent 从中取材回答或整理报告。
- **知识库是原始材料**：模型写入为「摘录原文 + 出处」，不是模型自撰总结；报告属派生物，进洞察不进库；派生物不得回流。
- 存储形态：**存抽取正文 + 存原始链接 + 不存原件**（省空间不是真问题，检索与链接失效才是）。
- 操作逻辑四条：①点开新信息即算已读；②卡片点开是消息列表；③实体在对话里由模型建、进待采纳区；④准确性优先「没有就没有」，讨论后采纳可入库，官网来源可自动入库**但须有证据**。

**尚未决定**：①「鼠标进入工作区」的判定需与并行 `CR-20260911-display-console-ux` 的「对话面板悬停态」合并为一条规则；②容量是否作为看板主轴（取决于容量数据能否收齐）；③科幻动画的具体形态与性能预算；④自动巡检成本待实测。
