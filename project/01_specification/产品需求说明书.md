# 产品需求说明书

责任人：产品 owner

## 产品目标

交付 Agent-Jarvis 的第一个产品功能：一个本机运行的底部悬浮大模型对话 UI。当前版本**以单一本地管理员身份运行**，用户在底部悬浮输入条发起文本对话，查看流式回复，随时停止，开启新对话，并保存最近会话。可用模型 Provider 的**启用与使用优先级在「配置」中管理**，对话浮窗不做 Provider/模型选择。

## 用户范围

- 主要用户：本机使用 Agent-Jarvis 的**单一本地管理员**（当前版本不区分多用户，无账号登录）。
- 管理职责：该管理员在「配置」中启用模型 Provider、设定使用优先级、维护凭据。

- REQ-F-008：`oauth` 认证模式在本版本仅作展示，不可保存为可用 Provider。

- 首页「知识库概览」区域在当前版本不展示，属已批准的暂缓项，不构成需求删除。

### CR-20260909-minimal-floating-chat 澄清

**会话生命周期**
- 会话自**首条用户消息**创建，至用户点击**「停止」或「新对话」**结束。
- 活动中：多轮续接，每次发送沿用同一 `conversationId`；回复正常完成后会话仍活动，可继续追问。
- 已结束：`conversationId` 丢弃；记录区在「点击新对话」或「发送下一条消息」时清空；下一条消息创建新会话。
- 已结束/已停止的会话及其消息保留在本地存储，本版本无浏览入口，且不被刷新恢复逻辑捞取。

**请求级错误 vs 流中错误**
- 请求级错误（回复第一段文本到达前失败：连接失败/鉴权失败/Provider 4xx-5xx/超时）→ 输入框上方一行红字，脱敏，不写入上下文，不结束会话，不阻塞输入。
- 流中错误（回复已开始后中断）→ 该助手气泡标记「生成失败」，落库 `status=error`（现有行为）。

**面板高度**：展开后对话面板高度上限由视口 65% 收敛为 **50%**（覆盖 CR-20260908-ui-light-theme-minimal-home 的 65% 澄清）。

**动作按钮状态机**（单个按钮）

| 场景 | 按钮 | 行为 |
|---|---|---|
| 生成中 | 停止 | abort，服务端停止请求模型，会话结束，落库 `stopped` |
| 输入框有字 | 发送 | 发送，Enter 等效 |
| 输入框空（有/无历史均同） | 新对话 | 清空记录区，丢弃 `conversationId` |

**优先级解析**：见 REQ-F-006 验收 ④⑤⑥。状态灯反映「是否存在任一连接有效的 Provider」；发送时取连接有效的 Provider 中优先级最高者。

**REQ-F-001 暂缓边界**：当前版本以单一本地管理员身份运行，不实现账号登录；「账号登录」按钮保留为占位入口。恢复 Google 登录时同步恢复 REQ-F-001 与 REQ-NF-002。

### CR-20260909-collapsible-panel 澄清

**折叠状态语义**（REQ-F-019）：收起/展开是纯 UI 态，不影响 `conversationId`、`jarvis:chat-session-ended`，不触发或结束会话；与「新对话」「停止」正交。持久化用 `localStorage['jarvis:chat-collapsed']`（每浏览器）；`localStorage` 服务端不可读，SSR 首帧按默认（展开）渲染，hydration 后按存储校正——只接受一帧内校正，不接受持久错误态（与 DEC-011 同类处理）。

**折叠期间回复完成提示**：仅状态灯一次短促瞬时提示，不引入未读角标、消息计数或第五种持久灯态。

**折叠时的请求级错误红字**：折叠状态下记录区不在 DOM，但请求级错误红字**照常显示在输入框上方**（它关联「发送」动作，输入条始终可见）。

**折叠可访问性**：折叠时 `aria-live` 记录区随之移除，屏幕阅读器用户在折叠期间不朗读流式回复——与视力用户对等（都需展开查看内容），非缺陷。

### CR-20260909-corner-menu 澄清

**左下角 ☰ 菜单**（REQ-F-015）：header 不再有功能按钮，标题独占顶部。☰ 触发器 `position: fixed` 于左下角，层叠高于底部悬浮对话（`z-index` > 20），对话折叠或展开时均可点击。浮层菜单为**非模态** disclosure（Esc 关 + 焦点回触发器 + 点击外部关闭）；「模型」「账号登录」两项仍打开各自的模态 `<dialog>`。浮层机制（原生 `popover` 属性 vs 自写 disclosure）留 P3。

**主题开关内联**：浅色/深色切换从「模型」（原「配置」）弹窗的「外观」分区移出，作为 ☰ 浮层内的内联控件——点击**不打开任何弹窗**，当场切换并写 `localStorage['jarvis-theme']`（`ThemeToggle` 组件与持久化机制不变，仅换宿主）。

**「配置」→「模型」**：首页该入口的按钮/菜单项文案由「配置」改为「模型」，打开的仍是同一个 Provider 设置弹窗（内部标题不强制改）。「配置」一词在配置预检（`config:check`）、`ConfigWarning` 等其它上下文不受影响。

**dev 指示器**：`next.config.mjs` 设 `devIndicators: { position: "bottom-right" }`，把 Next.js dev 模式指示器挪到右下角，避免与左下角 ☰ 冲突。这是构建配置，不在应用组件里做 `NODE_ENV` 分支；生产构建无 Next 指示器。

**可发现性取舍**：设置/账号入口在左下角属非行业惯例（惯例在右上角/汉堡菜单）。鉴于当前为单一本地管理员（配置一次即可），可发现性成本可接受——记为**有意取舍**，非遗漏。
