# 架构设计说明书

责任人：架构角色

## 设计目标

基于已批准产品需求，采用 Next.js 全栈架构实现本机运行的底部悬浮大模型对话功能。服务端负责身份态、Provider 配置与优先级、凭据加密、流式模型代理和会话持久化；前端负责占位登录入口、独立模型设置页（含优先级管理）、底部悬浮对话 UI 和流式展示。当前版本（CR-20260909-minimal-floating-chat）以单一本地管理员身份运行，Google 登录（REQ-F-001）与多用户隔离（REQ-NF-002）暂缓。

## 总体架构

```text
Browser UI
  -> Next.js App Router pages
  -> Auth.js Google session
  -> API routes
  -> SQLite persistence
  -> Provider adapters
  -> OpenAI / DeepSeek / Local OpenAI-compatible endpoints
```

## 接口契约

### Provider

```ts
type ProviderAuthMode = "oauth" | "api_key" | "local" | "unsupported";
type ProviderKind = "openai" | "deepseek" | "local";

type ProviderSummary = {
  id: string;
  name: string;
  kind: ProviderKind;
  authMode: ProviderAuthMode;
  baseUrl: string | null;
  defaultModel: string;
  enabled: boolean;
  connected: boolean;
  priority: number;          // CR-20260909：越小越优先；新启用者取当前最大 + 1
  secretPreview: string | null;
};
```

`resolveActiveProvider(userId)`（MOD-PROVIDER，CR-20260909）：返回 `enabled && connected` 的 Provider 中 `priority` 最小者及其 `defaultModel`，皆不满足时返回 `null`（→ 状态灯灭、发送被拦截）。`connected` 取 REQ-F-018 加载探测的当次结果。

### ChatDelta

```ts
type ChatDelta =
  | { type: "start"; conversationId: string; messageId: string }
  | { type: "delta"; text: string }
  | { type: "stopped" }
  | { type: "error"; message: string }
  | { type: "done"; messageId: string };
```
