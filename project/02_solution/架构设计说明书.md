# 架构设计说明书

责任人：架构角色

## 设计目标

基于已批准产品需求，采用 Next.js 全栈架构实现本机运行的底部悬浮大模型对话功能。服务端负责身份态、Provider 配置与优先级、凭据加密、流式模型代理和会话持久化；前端负责占位登录入口、独立模型设置页（含优先级管理）、底部悬浮对话 UI 和流式展示。当前版本（CR-20260909-minimal-floating-chat）以单一本地管理员身份运行，Google 登录（REQ-F-001）与多用户隔离（REQ-NF-002）暂缓。

## 架构角色定位与文档范围

**架构角色负责（本文档的权威边界）**：技术选型与版本、部署与运行形态、模块划分与边界、模块间接口契约、数据模型与迁移策略、状态流、外部依赖边界、跨模块的非功能约束（安全、性能、可测性）与架构决策记录（DEC）。

**架构角色不负责**：产品功能定义与验收标准（产品需求说明书）、具体实现代码（模块开发角色）、测试用例设计（测试角色）。当架构约束与产品需求冲突时，按 `docs/WORKFLOW.md` 失败回流：架构 → 产品需求 → 用户确认。

**本文档对每个产品需求变化点必须给出架构裁决**：不涉及架构（纯文档/纯实现）、既有决策已覆盖、需新增或修订 DEC。模块任务开发说明书据此逐点派生任务。

## 技术栈与部署形态

### 运行形态

单进程全栈：一个 Node.js 进程同时提供前端渲染与后端 API，无独立后端服务、无反向代理、无消息队列。数据落在项目运行目录下的单个 SQLite 文件。面向单机单用户（当前单管理员），并发规模为 1。

### 部署方式

| 环境 | 命令 | 构建目录 | 说明 |
|---|---|---|---|
| 交互开发 | `npm run dev` | `.next/` | 当前唯一实际使用形态（REQ-NF-001） |
| 生产构建（本机） | `npm run build` + `npm start` | `.next/` | 可用但当前无验收；`JARVIS_TEST_USER_ID` 旁路在此不生效（见 DEC-001 备注） |
| 验证构建 | `npm run build:verify` | `.next-verify/` | 构建目录隔离（DEC-009） |

非目标（产品需求说明书）：无容器化、无公网部署、无 CI/CD 发布管线、无多实例。发布控制见 `project/07_releases/版本发布控制说明书.md`（本机分发）。

### 前端技术

| 项 | 选择 | 依据 |
|---|---|---|
| 框架 | Next.js 15 App Router + React 19（RSC + 客户端组件） | 全栈同构、SSR 注水、Route Handler 与页面同仓 |
| 语言 | TypeScript 5.9 | — |
| 样式与主题 | 全局 CSS + CSS 自定义属性做 theme-aware，无 CSS 框架、无组件库 | DEC-006；零依赖，无主题闪烁 |
| 弹窗 | 原生 `<dialog>` + `showModal()` | DEC-007；平台原生遮罩/焦点陷阱/Esc |
| Markdown | 自写 `src/lib/markdown.tsx`，输出 React 元素不经 innerHTML | DEC-008；无注入面、零依赖 |
| 流式消费 | `fetch` + `ReadableStream` reader 解析 SSE；`AbortController` 停止 | DEC-004 |
| 状态管理 | React 组件内 `useState`，无全局状态库 | 规模不需要 |

### 后端技术

| 项 | 选择 | 依据 |
|---|---|---|
| API 层 | Next.js Route Handlers（与前端同进程） | 单体全栈 |
| 持久化 | `node:sqlite`（`DatabaseSync`，Node 内置，需 Node 22+；当前 Node 24） | DEC-002；零外部数据库、零 ORM；类型垫片 `src/types/node-sqlite.d.ts` |
| 凭据加密 | `node:crypto` aes-256-gcm，密钥 `JARVIS_SECRET_KEY` fail-fast | REQ-F-009；`src/lib/crypto.ts` |
| 身份 | NextAuth 4（Google Provider）**代码保留但暂缓**；当前 `src/lib/auth-guard.ts` 单管理员旁路 | DEC-001 |
| 模型调用 | 统一走 OpenAI-compatible `/chat/completions`（原生 `fetch`），流式归一为 `ChatDelta`，超时 60s，错误体归一 | DEC-003；`src/lib/adapters.ts` |
| 流式输出 | SSE（`text/event-stream`），`ChatDelta` 事件 | DEC-004 |

### 依赖清单与边界

运行依赖（`dependencies`）：`next`、`react`、`react-dom`、`next-auth`。**`openai` 已声明但全仓库无 import**——属可清理的冗余依赖，P3 处理（CONTROLS 对外部依赖为 L3 敏感，移除按 L1）。
开发依赖：`vitest` + `@testing-library/*` + `jsdom`（组件/单元）、`@playwright/test`（真实入口）、`typescript`、`vite`。
新增任何运行依赖属 L3，须先经 CR。本 CR 不新增依赖。

### 关键运行配置

`.env.local`（不入库）：`JARVIS_SECRET_KEY`（必需）、`JARVIS_DB_PATH`、**`JARVIS_SKILLS_PATH`**（技能目录根，缺省 `<cwd>/.data/skills`；smoke/e2e/测试用它隔离，CR-20260909-skills）、`JARVIS_TEST_USER_ID`（当前单管理员形态使用）、`NEXTAUTH_URL`/`NEXTAUTH_SECRET`（暂缓项，占位）、`GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`（暂缓项，可空）。预检 `npm run config:check`（`scripts/check-config.mjs`）。

## 总体架构

```text
Browser UI
  -> Next.js App Router pages
  -> Auth.js Google session
  -> API routes
  -> SQLite persistence
  -> Provider adapters
  -> OpenAI / DeepSeek / Local OpenAI-compatible endpoints
```
