## 1. 问题一：长 HTML 报告「截断」且「未渲染」

### 1.1 实测时间线（会话「现在开始可以联网了吗」，2026-09-11）

`messages` 表按 `seq` 回放，只列 `save_insight` 相关行。参数长度取 `tool_calls[0].function.arguments` 的字符数；token 估算用 `estimateTokens`（CJK 1.5 字/token）。

| 02:21:45 | 6,464 | 2,110 | **是** | **0** | HTML 不完整或为空 |

两组失败的机理不同：

- **前 9 次**：参数在流中被切断，JSON 不闭合。参数尾部停在 `style=\"width:` 或 `</td></` 之类的半截标签。请求体不带 `max_tokens`；DeepSeek `deepseek-chat` 默认输出上限约 4K token。一份 18KB 中文 HTML 的实际 token 数超过该上限。`adapters.ts` 的 `ToolCallAccumulator` 有意不读 `finish_reason`（注释写明「DeepSeek 与本地运行时对它何时发送不一致」），因此被截断的工具调用原样下传，`parseToolArguments` 解析失败**静默返回空对象**，工具只能回复「不完整或为空」。模型得不到「被输出上限截断」这个关键信息。
- **后 4 次**：JSON 完整，但模型把参数写成了嵌套的 `{"arguments": {"html": "..."}}`。服务端读 `args.html` 得到 `undefined`，同样回复「不完整或为空」。63 字节的探针 HTML 也被拒绝，说明与长度无关。错误文案没有说出「缺少 html 字段、收到的键是 arguments」，模型无法自纠。

### 1.2 分块提交只能互相覆盖

模型从 02:23 起改为分块提交（后续会话的压缩摘要里记着「长 HTML 提交到中途会被截断」，所以 12:28 那轮一开始就分块）。`save_insight` 每次调用 `insertInsight` 新建一行并把 `display_state` 指向新行；`insights` 表三行的 `<h1>` 相同、章节互不重叠：

| 洞察 | 长度 | 章节 |
|---|---|---|
| 11301bbb | 3,528 | 摘要、白皮书横向比对 |
| 424c316c | 6,700 | 摘要、横向比对、纵向精读一、二 |
| 214c3e25 | 7,200 | 纵向精读（续）三、可比性分析四条结论、来源与局限 |

展示屏只指向最后一行，用户看到的就是「不完整」。REQ-F-024 ③ 写的「同一会话多次产出按 created_at 追加，不覆盖」指的是行不覆盖，展示屏指针却只有一个，工具没有「追加到同一份」的语义。

### 1.3 未渲染 = 没有样式

三行 HTML 均为裸 `<div>` 片段，`hasStyle=false`（无 `<style>`、无内联 `style=`）。技能自带的 `assets/html-report-template.html`（3,327 字节，含 `<style>`）本应作为外壳，模型为压缩长度把它丢了。`DisplayScreen` 用 `<iframe srcDoc>` 原样渲染，不注入任何基础样式，也不传递主题，所以表格无边框、标题无层级、深色主题下是白底黑字。

### 1.4 结论

| 层 | 缺陷 | 归属 |
|---|---|---|
| 适配器 | 不发 `max_tokens`；不读 `finish_reason=length`；截断不可见 | CP-4 |
| 工具注册表 | 参数解析静默失败；不识别嵌套包装；错误文案无信息量 | CP-3 |
| 展示工具 | 只能新建覆盖，不能追加到同一洞察 | CP-2 |
| 展示屏 | 无基础样式、不跟随主题 | CP-5 |

## 2. 问题二：☰ 菜单排版

Playwright 打开菜单后测量 `.corner-menu__panel` 与 `.floating-chat` 的包围盒（`shot.mjs` / `shot2.mjs`，一次性脚本）：

| 视口 | 面板 x / y / 宽 / 高 | 对话框 x / 宽 | 现象 |
|---|---|---|---|
| 1440×900 | 16 / 282 / 256 / 550 | 336 / 768 | 不重叠；面板占视口高 61% |
| 1024×700 | 16 / **-26** / 256 / 658 | 128 / 768 | 面板顶部被裁 26px，主题切换看不见；与对话框横向重叠 144px |
| 390×844 | 16 / 118 / 256 / 658 | 0 / 390 | 面板完全盖住输入区 |

代码事实（`CornerMenu.tsx`）：面板是 `w-64` 的绝对定位浮层，没有 `max-height`、没有 `overflow`、没有碰撞处理；子项由 `page.tsx` 以 children 传入，五种类型（主题分段控件、两个对话框入口按钮、技能列表卡片、知识库卡片、搜索设置表单）各自带不同的边框与标题样式。技能列表每项把完整 `description` 整段渲染（截图中一个技能占 6 行），技能越多面板越高。

业界参考：桌面端把「导航 / 动作」与「设置表单」分离——菜单只放入口行，表单进对话框或侧边抽屉；侧边抽屉（Sheet / Drawer）全高、内容区独立滚动、带遮罩，天然规避高度裁切与重叠；列表项一行一项，次要操作收进行尾更多菜单或悬停显示。

## 3. 问题三：对话面板缺少悬停态

1440×900 展开态实测：`.floating-chat` y=79，高 821，即面板从视口顶部 79px 一直铺到底，展示屏上的报告几乎全被遮住。REQ-F-003 已放宽到 75vh，加上工具条与输入行后仍接近满屏。现有收起是持久偏好（REQ-F-019，`localStorage`），每次看报告都要手点箭头、看完再点回来。

技术事实：展示屏内容在 `iframe` 里，指针进入 iframe 后父页面收不到 `mousemove`，但离开对话面板的 `pointerleave` 一定触发；因此「移到动态屏」可以用「离开面板且未进入其他浮层」判定，「回到对话框 / 准备输入」用 `pointerenter`、`focusin`、`keydown` 判定。REQ-F-019 ④ 要求折叠态下流式回复不自动展开——悬停态必须与它正交，不能互相覆盖。

## 4. 问题四：工具步数上限

时间线里 `status=truncated` 的助手行出现在 02:15:11、02:15:38、02:24:44 等处，每次用户都要回「继续」。一次「读技能 → 4 路搜索 → 4 路读页 → 再搜 → 再读」的研究型任务，10 步在第二轮读页就触顶。用户 2026-09-11 直接授权「先扩展到 100 次」，已当场实施：

| 项 | 值 |
|---|---|
| `MAX_TOOL_STEPS` | 10 → 100 |
| 测试 | `tests/agent-loop.test.ts` 触顶用例按常量跑 100 步后停止，PASS；`tests/chat-stream.test.ts` PASS（两文件共 24 用例） |
| 未同步 | 产品需求说明书 REQ-F-029 ①②、架构说明书 DEC-022 / MOD-TOOLS、模块与测试说明书 CP-1 与 P2 数值表仍写 10 |

成本边界：100 步意味着单轮最多 100 次模型调用。REQ-NF-007 预算、REQ-F-041 保留窗口、REQ-F-042 压缩三者仍然兜底；REQ-F-029 ④ 同参连续失败 2 次熔断不变。

## 5. 设计决策与依据

| # | 决策 | 依据 | 门 |
|---|---|---|---|
| D1 | `save_insight` 增加**追加到同一洞察**的能力，展示屏指针不动、内容刷新 | §1.2：分块是长内容的正确做法，缺的是追加语义；不改 schema（只更新 `html` 列） | 双向 |
| D2 | 请求带 `max_tokens`；适配器读 `finish_reason=length`；被截断的工具调用**不执行**，改回喂明确原因 | §1.1：截断不可见是根因；模型收到「在第 N 字符被截断」后才能正确决定分块 | 双向 |
| D3 | 参数解析兼容嵌套包装；缺字段回喂收到的键名 | §1.1 后 4 次失败 | 双向 |
| D4 | 展示屏注入基础样式与主题 token；洞察自带样式优先 | §1.3；用户原话「没有渲染」 | 双向 |
| D5 | ☰ 浮层改为左侧抽屉；设置表单入口化；技能行单行化 | §2 测量 + 业界做法；用户原话「参考业界的做法」 | 双向 |
| D6 | 面板新增 `autoHidden` 临时态，与 `userCollapsed` 正交，仅 hover 设备启用，流式中不收缩 | §3；用户原话「移到动态屏时自动收缩，移到对话框或者准备输入时展开」 | 双向 |

## 8. 本 CR 依赖人工发现的风险

- **报告观感**（CP-5）：机器守得住「iframe 文档含基础样式且 `data-theme` 与宿主一致」，「报告好不好看」只有真实使用才知道。
- **悬停体验**（CP-8）：机器守得住状态机（离开 → 延迟 → 收缩；进入 / 聚焦 / 按键 → 展开；流式中不收缩），「会不会闪」「延迟合不合手」需真实入口试用。
- **抽屉信息架构**（CP-6/7）：分组与顺序是判断题，不是测试题。
