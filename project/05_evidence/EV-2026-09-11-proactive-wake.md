## 1. 单次唤醒的真实成本（本 CR 全部成本边界的依据）

D 期的核心约束来自用户原话：「借鉴 openclaw 的主动唤醒，但不消耗大量 token」。A 期已量过 OpenClaw 的结构性开销（每轮 ≈ 8000 token 固定注入）。所以先量一下：**如果唤醒只带最近对话的一小段尾巴**，一次到底多少 token。

对本机最近 9 个真实会话，用 `buildWakeMessages`（`src/lib/wake.ts` 的同一实现：固定指令 + 最近 12 条用户/助手文本，按 1500 token 从头截断）计算单次唤醒的输入 token：

| 会话（按更新时间倒序） | 单次唤醒输入 token |
|---|---|
| 1 | 1,577 |
| 2 | 956 |
| 3 | 1,611 |
| 4 | 215 |
| 5 | 1,608 |
| 6 | 306 |
| 7 | 1,042 |
| 8 | 270 |
| 9 | 232 |

| 统计 | 数值 |
|---|---|
| 最小 / 中位 / 最大 | 215 / 956 / **1,611** |
| 其中固定指令部分 | 111 |
| 输出上限（`max_tokens`） | 200 |

### 两个结论

**① 上限起作用了。** 三个长会话都被截到 1,611（= 1,500 上下文上限 + 111 固定指令），不随会话长度增长。这是与 OpenClaw「全量注入」的本质区别：唤醒成本有天花板。

**② 但间隔一小、次数一多，仍然可观。** 按默认 30 分钟一次、页面可见一整天（48 次）、每次最坏 1,611 + 200 计，**上限 ≈ 86,900 token / 天**——比一个用户一天正常对话可能都多。所以：

- 单次有界不够，还要**日上限**。默认 20,000 token / 天 ≈ 最坏 11 次、中位 17 次唤醒，够一个工作日用，超了就停到明天；
- **默认关**（用户终裁 5），开关旁边直接显示今日已用；
- 只在**页面可见且用户安静了一个完整间隔**时才触发——对着隐藏标签页唤醒是没人看的 token，对着正在打字的用户唤醒是打断。

### 复算方法

一次性测算，`node:sqlite` 只读打开开发库，取 `conversations` 最近 9 条，各自 `listMessages` 后喂给 `buildWakeMessages`，用 `estimateTokens` 累加两条消息；数值随会话内容变化，方法可重跑。

## 2. 设计决策与其依据

| # | 决策 | 依据 | 门 |
|---|---|---|---|
| D1 | 唤醒 = **一次非流式调用**：固定指令 + 最近对话尾巴（≤ 1,500 token）+ 输出 ≤ 200；无工具循环 | §1；用户「不消耗大量 token」；OpenClaw 的 heartbeat 之所以贵是因为带全套上下文和工具 | 双向 |
| D2 | **默认关 + 开关 + 间隔 + 日上限**，全部存 `app_settings` 键值表，**无 schema 变更** | 用户终裁 5「默认关，要有开关」；附录 C「空闲态 token 上限」；与 B/C 期同一手法避免迁移 | 双向 |
| D3 | 产出 **NOOP 即静默**（不显示、不落库，但计 token）；有内容才落为 `system` 行、状态 `wake`、前缀「主动提醒：」 | 「不打断」——没事就什么都不出现；有事一条系统行，不是助手气泡（它不是回答） | 双向 |
| D4 | 提醒行**绝不回放进模型上下文**（`wake` 不在 `REPLAYABLE_STATUSES`；唤醒提示也不含早前提醒） | 否则唤醒会吃自己的产物、越唤越多——这是 fail-open 的对偶：静默失败之外还要防自激 | 双向 |
| D5 | 触发在客户端（页面可见 + 无流式 + 安静满一个间隔），**授权在服务端**（开关与日上限由服务端判定） | 客户端定时器只是触发器，不能成为花钱的权限来源；隐藏标签页不唤醒 | 双向 |
| D6 | ☰ 提供「现在唤醒」：忽略开关、不忽略日上限 | 用户能先看一次唤醒长什么样再决定开不开；也是真实入口用例的入口（不等 30 分钟） | 双向 |
| D7 | 调用失败静默跳过，但把输入 token 计入日用量 | 失败的请求可能已计费；不计会让坏 Provider 在无声中烧完预算 | 双向 |

## 4. 本 CR 依赖人工发现的风险

**唤醒内容是否「值得提醒」**（CP-3）：模型可能把不值一提的事拿来提醒，或漏掉该提醒的。机器守得住的是形状（NOOP 静默、有内容才落行、有界、不回放）；提醒质量只有用户在使用中感受。默认关与日上限使这一风险的代价有上限。
