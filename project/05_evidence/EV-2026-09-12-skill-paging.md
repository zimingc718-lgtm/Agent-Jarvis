## 1. 技能：从「截断的一大块」到「可翻阅的一组」

### 1.1 改前的机制

`read_skill` 走 `resolveSkillForTurn`：把 SKILL.md 与文件夹里每一个白名单文本文件**首尾相连**，按 32KB 截断，再由工具按 8,000 token 截断一次。

后果有两层：

1. **量**：大部分内容进不去；
2. **哪一部分进得去由字母序决定**——`assets/` 排在 `references/` 前面，于是一个大模板可以把后面所有参考文件挤出去，而这完全不取决于它们跟当前任务的相关性。

### 1.2 真实技能实测

`.data/skills/multi-agent-insight-reviewer`：

| 指标 | 值 |
|---|---|
| SKILL.md | 3,680 字符 |
| 其余文件 | **20 个，合计 160 KB** |
| 最大三个 | `references/review-rubric.md` 20 KB、`references/react-multi-agent-workflow.md` 14 KB、`references/report-templates.md` 13 KB |

| | 改前 | 改后 |
|---|---|---|
| 入口一次给模型 | 32 KB 拼接块 | **4,480 字符**（SKILL.md + 20 项清单） |
| 永远看不到的部分 | **128 KB** | **0**，按需逐个读 |

评审标准、工作流、报告模板——这三份恰恰是决定报告质量的东西，改前它们大概率落在被截断的那 128 KB 里。

### 1.3 处置

`read_skill(name)` 返回 SKILL.md 正文 + 文件清单（含每个文件的 KB 数）；`read_skill(name, file)` 单独取一个文件，按本轮预算截断并说明。

宿主约定补了第 7 条，明说参考文件不会一次性给到、动手前先按清单读相关的那几个、不要凭技能名猜它的规范。

按文件读取带路径守卫，形状与 `documents.ts`、`url-guard` 一致：先 `realpath` 再用 `relative()` 判包含。`references/../../.env` 这类在解析后的路径上被拒，不是在字符串上。非白名单格式（如 `.png`）也拒。

### 1.4 顺带删掉的旧实现

`resolveSkillForTurn` 在本次改动后**生产代码里已无人调用**，只剩测试引用；`TRUNCATION_NOTICE` 与 `truncateToBytes` 亦然。按 `CLAUDE.md` 交付纪律「被取代的旧实现要在同一变更内删掉」，三者一并删除。

对应的三处测试没有删，而是**迁移**——它们的意图仍然成立，只是机制换了：

| 原断言 | 迁移后 |
|---|---|
| 拼接结果含 SKILL.md 与白名单文件、排除非白名单 | `readSkillDoc` 返回正文；`listSkillFiles` 列出白名单文件、排除非白名单 |
| 超 32KB 截断并标注 | 大文件不再挤掉小文件：两者都在清单里，各自按预算单独取 |
| 技能库每本注入都在 32KB 内 | 每本 SKILL.md 非空且入口大小不再取决于参考文件体量 |
| 扩展名放宽后这些文件出现在注入里 | 这些文件出现在文件清单里 |

## 2. 控制台高度

上一条 CR 记了一项未解决：报告列（68% 居中，1440 视口下 980 px）与对话面板（768 px 居中）共用中轴，实测水平重叠 78%。

彻底解法是让两者不争同一条中轴，属更大的布局改动。本 CR 只动**纵向**这一处：

`hasSteps` 分支由 `max-h-[75vh]` 降到 `max-h-[58vh]`。这个分支恰恰是报告轮次会命中的那个（多步工具调用 → 步骤流很长），1440×900 下面板总高由 821 px 降到约 640 px，报告顶部因此始终可读。58vh 仍能显示十余行步骤。

UI 契约 RF-09 要求两档上限满足「低档 ≤ 55、高档 ≤ 80」，改后为 50 / 58，仍然满足。

**期间踩到一个坑并记下**：把说明写成多行注释插进 `cn()` 的参数列表后，`ui-contract` 的 RF-07 与 RF-09 立刻 FAIL——该检查是扫类名附近的工具类字符串，注释把提取窗口割断了，于是「找不到高度上限」。注释移到元素之前即恢复。这一点写进了代码注释本身。

## 4. 未覆盖的部分（如实登记）

- **模型是否真的按清单去读**属提示层。约定写了、清单给了体量，但它会不会先读评审标准再动笔，机器断言不了。这一条要下一次真实使用才知道。
- **共用中轴的横向冲突仍在**。本 CR 只降了纵向高度；用户手动展开面板时，报告横向仍被盖住大部分。彻底解法需要让报告列与控制台分占不同横向区域，是更大的改动。
- **清单不含相关性排序**。按路径字母序列出，模型自己判断先读哪个。按任务相关性排序需要额外判断，本期不做。
- **单文件仍有 8,000 token 上限**。一个超过该上限的参考文件仍会被截断，只是不再因此挤掉别的文件。
- **技能库里的旧技能没有重写**。它们仍是为别的宿主写的，本 CR 让它们**可被完整读到**，但没有改写其内容。
