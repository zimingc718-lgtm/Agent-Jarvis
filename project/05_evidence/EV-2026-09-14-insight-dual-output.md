## 1. 为什么 Markdown 是派生物而不是第二份作者产物

让模型同时写 HTML 与 Markdown，要多花一遍 token，而且**两份正文迟早对不上**——改了一份忘了另一份，之后谁也说不清哪份是准的。

所以：HTML 仍是唯一作者产物，Markdown 由同一份 HTML 转换而来。代价是转换器得自己写，它只覆盖模型实际会写出的标签子集，并守一条硬规矩：**认不出的标签只脱壳、不丢字**。转换可以丢格式，不能丢内容。

## 2. 写用户磁盘是单向门，所以边界写在结构里

这是本项目第一次往用户磁盘写文件。`git revert` 撤不回已经写下去的东西，因此三道边界不是靠调用方小心，而是靠结构：

| 边界 | 怎么保证 | 断言 |
|---|---|---|
| 只写在已配置文档根之内 | `realpath` 先解析再用 `relative()` 判包含（与 REQ-NF-050 ① 同一条纪律） | TEST-320 ⑮：越界目录被拒，且目标目录里什么都没有 |
| 永不覆盖 | `freePath` **只在 `stat` 抛错（文件不存在）时返回该路径**，没有任何分支能走到覆盖 | TEST-320 ⑲：连续归档两次，两个路径不同、两份内容都在 |
| 只新建，不改写既有文件 | 写入实现独立成 `insight-export.ts`；`documents.ts` 仍不导出任何写函数 | `document-tools` ⑤ 的既有断言继续成立 |

REQ-F-110 ⑤ 原文是「只读：不复制、不改写、不移动、不删除用户的任何文件」。本 CR 让它不再完全成立，所以**当场改准**——留着一条与实现相反的需求，比没有那条需求更坏。改法是把边界收窄到「本层无写入口」，并明列唯一例外。

## 4. 真实入口（2026-09-14，用户自己那台服务器，端口 3000）

生产构建 + `serve:local`，全程走真实 HTTP 接口，用的是**用户知识库里那份 23,434 字符的真实报告**（`0c4ddb34-…`，2026-09-13 生成）：

| 步 | 请求 | 结果 |
|---|---|---|
| 1 | `GET /api/settings/documents` | `{"roots":[],"archive":""}`——记录改前状态 |
| 2 | `POST` 加一个临时文档根 | ok |
| 3 | `PATCH {"archive":"C:/Windows/Temp"}` | **400**：「归档目录不在任何已配置的文档目录之内，已拒绝——写入范围不会超出你已经授权的那些文件夹。」 |
| 4 | `PATCH` 根内的 `报告/`（尚不存在） | ok，第一次归档时建出来 |
| 5 | `POST /api/insights/archive` | ok，18,923 字节，id `realentry-docs/报告/2026-09-14-AIDC-供电架构的代际切换：-从-54-VDC-机架到-800-VDC-直流母线.md` |
| 6 | 恢复设置（清归档目录、删临时根） | `{"roots":[],"archive":""}`，`app_settings` 里与 documents 相关的行为空——**用户的配置回到改前的样子** |

**不丢字的机器复核**：把源 HTML 去标签去空白得到 6,165 字正文，检查它是否为归档 Markdown 的**子序列**（Markdown 会在正文里插入 `#`、`**`、`|` 等语法字符，所以「连续一段」不成立，但每个字必须按原顺序出现）——结果 `True`，一个字都没掉。

> 第一版复核用的是「把源文本切成 40 字一段，逐段在归档里找」，报告 155 段里 126 段找不到。那是**判据错了**不是实现错了：Markdown 的语法字符插在正文中间，连续段本来就不成立。换成子序列检查才是对的判据。

## 5. 没有验到的（如实登记）

- **浏览器里点那个按钮这一下没做**。验的是按钮调用的那条 API，在用户自己那台服务器上、用他自己的真实报告。按钮到 API 之间的接线由 TEST-320 ⑪⑫ 以组件测覆盖（点击 → 调用 → 就地显示结果）。证据按 DEC-210 ③ 标 `entry: user`。
- **磁盘写满 / 无权限**：抛出的是 Node 原始错误，被 API 包成 400 回显。没有测试覆盖，**登记为人工发现项**。
- **转换的观感**：断言守住「不丢字」，守不住「好不好看」。一份表格套表格的报告转出来会难看，但不会缺内容。
- **归档文件名带全角冒号**（`：`，来自报告标题）。Windows 只禁 ASCII 冒号，实测写入成功；若将来要跨平台同步，这条可能需要再收紧。
