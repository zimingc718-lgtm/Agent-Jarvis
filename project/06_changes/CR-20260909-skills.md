- 方案选项:
  - A. 会话进入「技能模式」，整段会话都走该技能（被用户否决：msg 51 第 11 点，要 ChatGPT 式「某条消息提及则该轮触发」）
  - B. **每次发送前一次独立最小路由 LLM 调用判定 `{skill}`，命中则仅当轮注入技能内容；HTML 产出捕获入 `insights` 表；技能创建 = 拖文件夹到对话框 → LLM 生成 `SKILL.md` → 注册**
  - C. 用户手动 `/skill <name>` 显式前缀触发（无路由调用）——省一次 LLM 调用，但用户否决了「拖到菜单栏技能区」并要求「参考 ChatGPT 对话里的 skill 使用」，倾向自动路由
- 选择理由: 选 B。用户要"在对话里像 ChatGPT 那样用技能"——路由必须自动且逐条判定。路由做成**独立最小 LLM 调用**（架构-CP，DEC-016）避免污染主对话上下文、且路由失败 fail-open 不打断对话。技能内容**仅当轮注入**符合 msg 51 第 11 点。HTML 产出与展示解耦：F1 只捕获 + 落库 + 提供 `GET /api/insights` 读回（满足原则 13 的真实消费者），全屏动态展示屏归 CR-20260909-display-screen（用户 msg 54 第 3 点"两个CR"）。用户 msg 54 第 1 点明确**放弃 `<iframe sandbox>`**——架构记高危 DEC-015 + "沙箱化"为未来 CR 出口义务 + known warning `skill-html-unsandboxed` + 展示屏首渲提示条。
