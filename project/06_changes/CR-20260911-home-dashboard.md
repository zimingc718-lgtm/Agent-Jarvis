## 角色意见

标准档只取与本 CR 直接相关的角色意见。

| 角色 | 意见 | 处理 |
|---|---|---|
| 产品 owner | ①用户把知识库定性为「原始材料」，因此模型写入应是**摘录原文 + 出处**，不是模型自撰总结；报告属派生物不入库。②「没有就没有」必须落成可执行判据，否则只是态度。③卡片不能变成第二个应用——步骤流与状态灯都在对话框里，卡里再来一套是两套真相。 | CP-4/CP-5 成文；卡片只做源管理 + 交给对话框（CP-8） |
| 架构角色 | ①沿用 DEC-031 的文件模型，全部 CP 保持双向。②`stale` 必须推算而不是存死值：存死值会在源修好后继续显示陈旧。③直写判据放工具边界，不放模型，也不放路由——路由是用户自己的动作，本来就可信。 | DEC-050 ②④；`effectiveHealth` 为纯函数 |
| 测试角色 | ①健康度的核心断言不是「字段等于某值」，而是**「加了源但从未采集 = stale 而不是 fresh」**与**「最近采集过但解析失败 = parse_failed 而不是 fresh」**。②直写判据要有「未登记任何源的对象，任何来源都不能直写」这一例，否则白名单可被空列表绕过。③空看板必须断言「不假装有数据」。 | TEST-120 健康度四例、TEST-121 ⑧、TEST-123 ⑨ |
