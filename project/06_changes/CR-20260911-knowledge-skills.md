## 角色意见

标准档只取与本 CR 直接相关的角色意见。

| 角色 | 意见 |
|---|---|
| 产品 | 纪律类必须先装。用户定的「没有就没有」现在有了机器判据（`extract_fields` 的三道核对），但判据只会拒绝，不会教；证据规范是教的那一半。 |
| 架构 | 不要为装技能新开代码路径。既有登记入口已经处理了路径穿越、扩展名白名单、注入预算三件事，绕过它等于把这三件事重做一遍。 |
| 模块开发 | 技能文档里凡提到工具行为的地方，必须与实现一致（同域直写、待采纳、引文逐字核对）。写错的说明书比没有说明书更糟——它会让模型去做一件被机器拒绝的事，然后反复重试。 |
| 测试 | 只断言形状。把「模型是否遵守」写成断言就是假覆盖，CP-3 如实登记为真实入口。 |
