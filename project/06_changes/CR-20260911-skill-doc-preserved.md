## 缺陷经过

用户让我把仓库里的六本技能装进应用。装之前读了一遍登记路径，发现：

`registerSkill` 先把上传的文件原样落盘，**随后无条件调用 `generateSkillDoc` 并用其结果覆盖 `SKILL.md`**。没有配 Provider 时 `generateSkillDoc` 直接返回兜底值（`body` 为空串），`buildSkillMd` 于是写出：

```
---
name: <文件夹 slug>
description: （未生成描述）
---

（未生成描述，请补充本技能的说明）
```

也就是说：**把一个自带 `SKILL.md` 的文件夹拖进来，正文会被静默替换成一句占位符**。原文件除了这一份副本之外不在别处，等于丢失。配了 Provider 的情况稍好但同样不对——模型会把作者写好的指令转述一遍。

这条路径此前没有被发现，是因为既有测试里的 `files` 都只含 `readme.md`，没有一个用例给出自带 `SKILL.md` 的文件夹。**缺的是那个用例，不是那行代码**。
