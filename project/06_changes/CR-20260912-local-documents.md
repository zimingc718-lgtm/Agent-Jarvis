## 角色意见

| 角色 | 意见 |
|---|---|
| 产品 | 要把两层的分工写进需求，否则下一个人又会把它们合并。本地原文档是**事实来源**，用户的文件，只读；知识库是**沉淀**，模型提炼、用户采纳。合并过一次就够了。 |
| 架构 | 这一层把用户磁盘暴露给一个会读网页的模型，守卫不能自己发明。照抄 `url-guard` 已经验证过的形状：先解析再判包含。另外包含判定别用 `startsWith`——`/srv/docs` 会显得包含 `/srv/docs-private`，这个坑在文件系统里比在 URL 里更容易踩。 |
| 模块开发 | 三个工具必须无条件注册。`search_knowledge` 就是因为按 `knowledgeCount > 0` 决定注册，结果知识库空的时候模型连它存在都不知道，只能凭记忆答而没人看得出来。同一个错误不要犯第二次。 |
| 测试 | 两点。一是「只读」要能断言，不能只写在注释里——我对模块导出名做正则，出现任何写函数就红。二是新工具挤掉了 `read_entity`，我**不改那条断言**：它守的是看板能用，是对的。改注册顺序让文档工具在小窗口下让位，再断言它们出现在「未加载」名录里——被说明和被静默丢弃是两回事。 |

## R1 人工终裁

用户 2026-09-12 在确认需求理解后回复「好的，先做本地原档层」，构成直接授权。

以下 3 项记为**按助手建议采纳、待追认**，可单独撤回：

1. **可读格式限定为 PDF / .docx / Markdown / 文本 / CSV / JSON**。旧的 `.doc` 二进制格式、扫描件 PDF（无文字层）、`.pptx` / `.xlsx` 本期不做，前两类会给出明确原因。若手头资料以 pptx/xlsx 为主，另立 CR。
2. **不做文件选择器，要求输入绝对路径**。理由见 CP-8：浏览器目录选择器给的是沙箱句柄，做出来是假的。
3. **索引只在内存里，不做持久化**。进程重启后第一次检索会重新抽取。对本机单用户可接受；若真实目录很大导致每次重启都明显卡顿，再立 CR 做磁盘缓存。
