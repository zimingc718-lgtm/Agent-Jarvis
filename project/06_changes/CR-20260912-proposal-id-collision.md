## 问题陈述（证据，非主张）

`src/lib/entity-proposals.ts:91-95`：

```js
id: `${input.name}-${input.field}-${createdAt.replace(/[^0-9]/g, "").slice(0, 14)}`
  .toLowerCase()
  .replace(/[^0-9a-z-]/g, "-")
  .replace(/-{2,}/g, "-"),
```

实体 slug `维谛技术-vertiv` 被剥成 `-vertiv`；字段名同样只留 ASCII——「液冷方案」无 ASCII 故为空，「800VDC 电源支持」留下 `800vdc`。时间戳 `slice(0, 14)` 只到**秒**。

实测：一次提交 4 个字段，`GET /api/entities` 只新增 2 条提议，存活的正是唯一带 ASCII 的两个：

```
id=-vertiv-20260912174330        field=液冷方案
id=-vertiv-800vdc-20260912174330 field=800VDC 电源支持
```

代码注释写的是「时间戳让同一参数的两条提议不撞」——作者防住了同字段重复，**没有防住同一秒内的不同中文字段**。

两点让这条比一般缺陷更严重：

1. **它专门丢中文。** 中文字段名是本产品的常态——「液冷方案形态」「标准组织席位」「CDU 单点故障冗余设计」都不含 ASCII。
2. **报的是成功。** UI 与工具 summary 说「写入 4 个字段」，用户不会知道自己丢了两个。已经丢掉的那些**无从发现**——这是 `docs/CONTROLS.md` 里「错误发现不了」的典型形态。

### 意见详述

**产品**｜接受方案，提一处呈现上的连带影响：新旧两种 id 形态将长期共存，所以**知识看板上任何依赖 id 做排序或分组的地方都会出现两种形状**。实测现有看板按 `createdAt` 排序而非按 id，所以本次不受影响；但这条要记进 DEC 的风险栏，以免以后有人顺手改成按 id 排序时踩到。另外「已提议 N 个字段，待采纳」这句文案我确认采纳——它把「提议」这个状态说出来了，而旧文案「写入」暗示了既成事实，这是两个不同的承诺。

**架构**｜一处须确认的新增依赖。`entity-proposals.ts` 目前只 import 了 `node:fs/promises`、`node:path` 与本地 `./entities`（第 1-3 行），**没有 crypto**。引入 `node:crypto` 的 `createHash` 本身没问题，但须确认该模块只在 Node 运行时执行——Next 的 edge runtime 不提供 `node:crypto`。实测它经 `/api/entities/*` 路由进入，这些路由未声明 edge runtime，故当前安全；但这一条要写进 DEC 的风险栏，因为一旦以后有人给这些路由加 `export const runtime = "edge"`，失败点会出现在一个看起来完全不相关的地方。另建议哈希输入用 `entity + "\0" + field` 而不是直接拼接——否则 `("ab", "c")` 与 `("a", "bc")` 会撞，这类边界在中英混排的字段名里不是纯理论。

**模块开发**｜可实现性通过，但指出一处依赖缺口。「汇总数字取实际落盘条数」要求 `proposeEntityUpdate` 能告诉调用方**这次写入是新增还是覆盖**，而当前的 `ProposalOutcome` 只有 `{ applied, proposal, entity? }`（`entity-proposals.ts:38-42`），**不报告是否覆盖了同 id 的旧提议**。哈希修好之后碰撞本应消失，届时「落盘条数 = 成功写入次数」成立；但 TEST-260 ③ 要构造「入参 4 落盘 2」这个场景来验证计数逻辑本身，这就需要能人为制造覆盖。建议实现时让 `proposeEntityUpdate` 显式回传一个「是否覆盖」的标志，否则 ③ 只能靠 mock 文件系统来写，测试会很脆。

**测试**｜好消息：①**不需要任何新机制就能写**。`proposeEntityUpdate` 的 `opts` 已经带 `now?: () => Date`（`entity-proposals.ts:85`），注入一个固定时刻即可精确构造「同一毫秒」，不必依赖真实计时或 sleep。这条断言因此是确定性的、可进必选清单的。②提醒一处容易写松的地方：①的断言必须检查「id 互不相同」**且**「四条提议全部落盘」——只断言 id 不同的话，一个把后来者静默丢弃的实现也能过。③ 依赖模块开发提到的覆盖标志，若最终没有该标志，我会把 ③ 降级登记为人工发现项而不是用 mock 硬凑。
