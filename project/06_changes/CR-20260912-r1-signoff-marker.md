## 问题陈述（证据，非主张）

`tools/governance.py:858`：

```python
if not re.search(r"R1[^\n]*(拍板|终裁|人工确认)", cr_text):
    findings.append(f"FAIL REVIEW_R1_BLOCKED {name}: no R1 human sign-off marker ...")
```

三点：

1. **判据是「同一行里同时出现 R1 与终裁类词」，不区分时态。** 2026-09-12 为四条新 CR 走 R1 时，实际满足该正则的句子是「**R1 时一并终裁**」——一句关于将来的承诺。四条 CR 因此全部报 `REVIEW_R1_PASS`，而用户当时一次板都还没拍。
2. **它防的是「漏写签置」，防不了「签置尚未发生」。** 这两件事的区别在本项目里是实质性的：R1 是**人工终止门**（`docs/WORKFLOW.md`：「人工终止 … 四角色 Agent 出意见 → 人拍板」），机器绿灯被误读成「人已经拍过了」，正是这道门存在的意义被架空的方式。
3. **修它会让既有记录集体变红。** 现有 38 条通过 R1 的记录，其签置痕迹是按旧判据的自由文本写的（例如 `CR-20260910-ui-foundation` 写的是「用户已完成 R1 人工终裁」，格式与新要求不同但语义正确）。所以本 CR 不是改一行正则就完事，须同时给出既有记录的迁移处置——这也是它级别定 L2 而非 L1 的原因。

## 同一函数上的第二处缺陷（2026-09-12 追加）

`review r*` 从**CP 登记表与「级别」**判定一条记录的去向（`governance.py:781-789`：无 CP 表且级别为 L1 或含 `pre-R1234` 才算合法跳过），**从不读「状态」字段**。后果：一条 `状态: REJECTED` 却仍带 CP 表的记录会被当作在途变更，在 R2–R4 永久报红——它按定义永远不会做 P2。而 `CLAUDE.md` 规定收口与提交以缺省全量结果为准，于是一条已作废的记录足以卡住整条分支的收口。

实际发生过：`CR-20260912-knowledge-retrieval` 作废后保留文件留痕，随即在全量 `check p2` 里产生 3 条无法消除的 FAIL；最终只能把内容并进 `CR-20260912-knowledge-attribution` 并删除文件（见该 CR「被本 CR 吸收的…」一节）。**这意味着当前模型下「作废但保留留痕」这件事做不到**，而这正是治理最需要留痕的一类记录。

是否与本 CR 的 R1 签置判据一并修，见 Q4。

- **Q4｜REJECTED 记录要不要被评审门跳过。** 与 Q3 不同：Q3 是「判据太松」，本条是「判据缺一个维度」。两者都在 `review r*` 这一个函数里，回滚边界相同，故助手倾向**并入本 CR**（与 Q3 的建议相反）。若并入，须一并定义：跳过是只看 `状态: REJECTED`，还是要求同时给出接收方 CR 的名字（避免用 REJECTED 逃避评审）。
