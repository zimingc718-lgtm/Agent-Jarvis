- 方案选项:
  - A. 报告列随面板开合左右让位——**用户明确否决**：「报告不用跟着位移」。且读到一半内容横移本身就难以接受。
  - B. **两条固定车道**（选中）：控制台宽屏下离开中轴、停进右侧定宽车道；洞察面预留同宽。控制台的横向占位是常量，开合只改高度，所以报告位置在几何上就不会变——不靠时序、不靠动画抑制。
  - C. 继续只靠自动收起——否决。已在上一条 CR 做过，用户手动展开面板时报告仍被盖住大半，这正是本次要解决的残留。
  - D. 把报告改成可拖拽/可折叠的分栏——否决。引入一个需要用户学习和维护的新交互，代价远大于一条固定车道。
- 选择理由: 选 B。①**用户的约束直接排除了 A**；②**B 让「不位移」成为几何性质而非实现技巧**：控制台展开与收起只改高度、不改左右边界，剩余区域恒定，报告列随之恒定——三档视口实测位置与宽度完全一致（EV §4）；③**冲突是实打实的**：改前 1440×900 下重叠 768 px，占报告列宽 78%（EV §2）；④车道宽度只定义一次，两侧引用同一个变量，杜绝「一边改了另一边没跟上」导致报告重新被盖或白留空带。

## 角色意见

| 角色 | 意见 |
|---|---|
| 产品 | 用户把话说死了：报告不能跟着动。那就别在「什么时候让位」上做文章，直接给两条固定车道——控制台开不开，报告都在原地。宽屏以下没这个空间，老老实实用自动收起。 |
| 架构 | 车道宽度必须只有一个定义。两处各写一个数，迟早一边改了另一边没跟上，结果要么报告又被盖住，要么白留一条空带，而且这种错误肉眼很难发现。用 CSS 变量，让契约去断言两边都引用了它。 |
| 模块开发 | iframe 里那条媒体查询是按 iframe 宽度算的，不是窗口宽度。车道一上，iframe 变成 960px，1024px 的断点就永久命中了——报告列直接摊满整条车道。这个联动不看实测发现不了。 |
| 测试 | LB-02 得改。车道化之后它照样 PASS，因为基础类里 `mx-auto` 还在——一条断言着不成立之事却还绿着的规则，比没有规则更坏。改成两半都断言。另外注释割断提取窗口这个坑，这一轮我们踩了两次，第二次是在已经写过教训之后——把规则名直接写进注释里。 |

## R1 人工终裁

用户 2026-09-12 对 `CR-20260912-skill-paging` 末尾的两项待追认逐条裁定：

1. **「报告不用跟着位移。」** —— 授权做横向彻底解法，并给出硬约束：报告位置不得随面板开合改变。本 CR 的两条固定车道即为据此设计。
2. **「由模型来判断吧。」** —— 追认技能文件清单维持按路径字母序 + 体量、不做相关性排序（CP-7，无代码改动）。

以下 1 项记为**按助手建议采纳、待追认**，可单独撤回：

- **车道宽度取 27rem（432 px）**。这是取值不是实测结论：控制台比原来的 768 px 窄了不少，长回复读起来更费行。若实际使用觉得窄，改 `globals.css` 里 `--jarvis-console-lane` 一处即可，报告面会自动跟着让出对应宽度。
