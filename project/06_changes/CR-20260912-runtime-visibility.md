## 角色意见

| 角色 | 意见 |
|---|---|
| 产品 | 别只是把英文换成中文。用户真正要判断的是「该重启服务还是该直接重试」，那就去问一下服务还在不在，然后分开说。时间戳也得有——没有时间的报错事后什么都对不上。 |
| 架构 | 运行时信息**不能**进稳定前缀。那张前缀的全部意义就是跨轮字节不变，换个模型就重写它，等于把 REQ-NF-008 ① 作废。放易变后缀，它本来就是为这种「会变但不是时钟」的东西准备的。 |
| 模块开发 | 看护脚本要能停下来。我见过的坏法是：构建缺了，脚本无限重启，后台空转一晚上没人知道。跑够 20 秒才算「曾经活着」，短命三次就停并说清楚。但清零一定要有，否则偶发内存杀攒三次就再也不起了。 |
| 测试 | 两件事。一是脚本是 `.mjs`，引不了 TS，那份常量副本迟早漂移——我加一条断言读脚本源码比对。二是运行时那行让每轮多一条 system 消息，`chat-stream` 的序列断言会红；那是预期结果，我更新它并顺手断言位置，不是放松它。 |
