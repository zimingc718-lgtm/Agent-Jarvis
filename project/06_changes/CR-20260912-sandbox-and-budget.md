## 角色意见

| 角色 | 意见 |
|---|---|
| 产品 | 提示条必须一起改。沙箱化之后还写「未做安全隔离」是错的，但直接删掉提示条更错——隔离的是权限，内容可信度一点没变。新文案要把这两件事分开说。 |
| 架构 | 只加 `sandbox` 不够，必须同时把 `allow-same-origin` 写成禁止项。这两个 token 一起出现等于没加，而且是最容易被后人「顺手补上」的回退方式，不能靠代码审查挡。 |
| 模块开发 | 轮内预算不能写成无条件收窄。跨轮那次改对了，是因为需求原文就没有预算前提；这里没有对应条款，而且一次发送里的结果全是当前任务的材料。照搬会把「读五页再汇总」直接做坏。 |
| 测试 | 我要反转两条自己写过的断言，这件事得写进变化点登记，不能悄悄改。原来那两条锁定的是一个明确登记为待偿还的状态，且都写了偿还方式是走 CR——所以这不是改测试迁就实现。另外 CP-5 的断言要检查返回的是**同一个数组引用**，否则「没收窄」这件事没法证明。 |
