## 问题陈述

`CR-20260911-display-console-ux` 的五项待人工终裁从 2026-09-11 挂到 2026-09-13：代码一直按助手代拟的方案跑着，需求行却写着「R1 待终裁」，于是 REQ-F-050/052/053/054 四条**既在用、又没批准**。

用户 2026-09-13 逐条给出裁定。其中第 5 项在「不留预览」之外**追加了一件新事**：

> 5.不留。但每次回到对话框，要滑到最新的那消息，也就是最底，而不是最初。

这是一个真缺陷：收起对话面板会把记录区从 DOM 移除（REQ-F-019 ②），再展开是一次**重新挂载**，滚动位置从 0 起算——用户每次展开看到的是最早的一条，要自己往下滚到头。消息没有变化，所以只依赖 `messages` 的那版滚动效果不会再跑。
