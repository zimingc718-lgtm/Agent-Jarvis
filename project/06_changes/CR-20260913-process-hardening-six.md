## 问题陈述

2026-09-12 的复盘找到的是同一个根因，换了六张脸：**我验的东西，和用户看的东西，不是同一个东西。**

- 用户两次说「看不到大模型接口的选择」。第一次我去修实现，第二次才发现服务跑的是九小时前的构建——代码在磁盘上，用户在浏览器里，中间隔着一个没人比对过的进程。
- REQ-F-170 ③（`__通用__` 显示为具名分组）与 REQ-F-180 ⑥（推断字段不得与有据字段视觉等同）都做到工具层就停了：通过条件里没有一句是关于用户看得到什么的，四道门照样全绿。
- 这几轮所有「真实入口已验」都跑在 3100/3200/3300 的一次性服务器上，数据目录另起、跑完即删。每一句证据都是真的，也都与用户屏幕上的东西无关——而记录里看不出这个区别。

六条建议逐一对应到「让这个差别被说出来」。

### CP-1 真实入口（2026-09-13，用户那台服务器，端口 3000）

`npm run build:local` + `npm run serve:local`，随后：

```
$ node scripts/check-dev-server.mjs
PASS served CSS carries compiled Tailwind output (115271 bytes)
  source: http://127.0.0.1:3000 (1 stylesheet(s))
  PASS served build matches HEAD (591cd471)
```

**这一跑当场逮到了本条建议自己的实现缺陷**：第一版把 `<meta>` 手写在 layout 的 `<head>` 里，App Router 会把它整个丢掉——单测五例全绿，服务器返回的 HTML 里一个字都没有。改用 `metadata.other` 后才真的出现在页面上。

一条只在构造输入上验过的护栏，正是它自己要治的那种东西。这一条写进 `src/app/layout.tsx` 的注释里，免得下一个人再踩。
