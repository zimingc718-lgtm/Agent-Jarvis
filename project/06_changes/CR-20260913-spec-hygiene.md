## 问题陈述

**三笔账都不是「没做完」，是「纸面不说真话」。**

1. **26 条需求挂在 `REVIEWING`**，而它们的 R1 早已终裁、实现任务全部 DONE、测试 PASS。根子是 `docs/CONTROLS.md` 只定义了状态词的含义，**从没说过谁在什么时候推进它**。2026-09-10 之前有人手工转，之后就没人转过。后果是「到底做完没有」只能靠人一条条翻——巡检时我自己翻了一遍才敢下结论。
2. **12 行表格的列数与表头不符**，全是写在反引号里的竖线（`p1|p2|p3`、`user|isolated`、`append|replace`）。这不是难看：TASK-161 / TASK-190 / TASK-200 三行被按列读错，于是 REQ-F-102、REQ-F-130、REQ-F-140 在任何按列取值的地方都显示为「没有任何任务实现它」——写状态判据的第一版就被这三行绊住，先以为是追溯断链。
3. **4 条需求把能力交给模型却不提人的一侧**（`check-human-side` 于 2026-09-13 点名）。其中三条的人的一侧本来就在（步骤流、搜索设置面板、知识看板），只是从没写进通过条件；REQ-NF-008 是真的没有，按判据明写「无（原因）」。
