## 问题经过

`KnowledgeDashboard` 的巡检间隔输入框改前只有 `onBlur`/`onChange` 两个处理器：`onChange` 只更新本地 state，真正的保存只在失焦（`onBlur`）时发起，且保存结果与另外三处服务端数据入口（挂载读取、后台 tick 刷新、开关保存、立即巡检按钮刷新）一样，都是直接 `.then(setSweep)`——用服务端返回的整份 `SweepState`覆盖本地状态。

这意味着：只要用户在输入框里打了字但还没失焦，恰好这时后台 tick 刷新（每 60 秒一次，仅当看板可见时）或另一次保存的结果落地，`setSweep` 会把整份状态换成服务端版本，其中的 `intervalMinutes` 是编辑前的旧值——用户刚打的字被静默换掉，输入框里的数字突然跳回旧值，且没有任何提示说明发生了什么。此外，唯一的保存路径是失焦，鼠标点到输入框外才会触发；不支持 Enter 立即提交；合法范围（30–1440 分钟）只有失焦保存越界报错时才看得到。
