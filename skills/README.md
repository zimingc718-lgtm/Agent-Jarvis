# skills/ — 技能源目录

这里放**技能文档的源**，一个文件夹一本技能，每个文件夹里至少有一个 `SKILL.md`。

它们是仓库内容，不是运行时数据：

- 运行时技能装在 `.data/skills/`（`JARVIS_SKILLS_PATH`），由 SQLite 里的登记记录指向，
  `.data/` 不进版本库。
- 这里的目录**不被任何运行代码读取**。放在仓库里只为一件事：让技能文档可以被版本化、
  被评审、被回滚。

## 怎么装进 Jarvis

在应用里把本目录下的**某一个文件夹**拖进技能区即可（CR-20260910-skill-intake 的既有入口）。
登记会把文件拷进 `.data/skills/<slug>/` 并写一条记录。文件夹里已经带了 `SKILL.md`，
所以不会触发模型生成描述那条路径。

改了这里的内容后，应用里那份**不会自动更新**——重新拖一次，或直接改 `.data/skills/` 下
对应的文件。

## 顺序

纪律类先于领域类（EV-2026-09-11-home-dashboard §9）：

| 优先 | 技能 |
|---|---|
| 1 | `知识条目规范` — 什么该入库、切多大、标题与归属怎么填 |
| 1 | `证据规范` — 什么算证据、什么能直写、拿不准时怎么标注 |
| 2 | `竞品跟踪` — 配哪些源、哪些变化值得记 |
| 2 | `并网规则跟踪` — 阶段词映射、窗口日期 |
| 2 | `客户技术准入解读` — 硬要求与软偏好 |
| 3 | `报告生成` — 结构、引用、不确定的标注 |

**为什么纪律类必须先装**：工具做的事是提高写入速度。没有前两本，工具越多，垃圾进库
越快。用户定的「没有就没有」要靠证据规范落成可执行判据，否则它只是一句态度。
