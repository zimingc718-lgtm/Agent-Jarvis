# 并网规则跟踪

跟踪对象里的「规则与准入方」是一类：**并网标准就是 TSO / DSO 这些机构发的**，所以
标准和发标准的机构不分家，一个对象同时承载「谁」和「他们要求什么」。

这类对象的价值集中在三件事：**当前有效的版本、正在征求意见的版本、以及截止日期。**

## 1. 配哪些源

| 优先 | 页面 | 说明 |
|---|---|---|
| 1 | 规则 / 导则的**版本索引页** | 有效版本与历史版本都在这儿，改动必留痕 |
| 1 | 征求意见 / 公示 栏目 | 截止日期在这儿，错过就没了 |
| 2 | 技术公告 / 通知列表 | 补充规定、临时要求 |
| 3 | 新闻稿 | 一般是前几类的转述 |

**PDF 是这行的常态。** 抓不到正文时照实说，不要用页面上的摘要冒充规范内容。

## 2. 阶段词怎么映射

各机构用词不一，但状态只有几种。写进字段时**统一成下面的说法，并在引文里保留原词**：

| 统一说法 | 常见原文 |
|---|---|
| 征求意见中 | 征求意见稿、draft for consultation、public consultation |
| 已发布未生效 | 已发布、发布稿、published（带未来生效日） |
| 现行有效 | 现行、in force、effective |
| 已废止 | 废止、superseded、withdrawn |

**不要把「征求意见稿」写成「新规」。** 两者对我们的意义完全不同：前者是可以去提意见
的窗口，后者是必须照办的要求。这是这类对象上最容易出的错，而且错了看不出来。

## 3. 窗口日期在哪找

按这个顺序找，找到就停：

1. 公示页面正文里的「意见反馈截止日期 / deadline for comments」。
2. 附件（通知 PDF）首页的落款与截止说明。
3. 版本索引页上该版本的「生效日期 / effective from」。

找到后写到对象的**下一里程碑**字段（`nextLabel` + `nextDate`），引文照抄那句话。
找不到就留空——**不要用「公告日 + 30 天」这类惯例算一个日期出来**，那是编的。

## 4. 要抽哪些字段

对这类对象，最值得维护的是：

- `summary`：这家机构管哪个区域、发哪一类规则，一句话。
- `nextLabel` / `nextDate`：最近的一个窗口（意见截止、生效日）。
- `capacity`：仅当该机构对接入容量有明确门槛时才填（例如「≥ 1 MW 需走 B 类流程」）。
- `change`：本次变化一行摘要。

写法遵守 [证据规范]：先 `ingest_url` 存条目，再 `extract_fields` 带逐字引文写入。

## 5. 摘要怎么写

- 好：`4110 导则 2026 版征求意见稿发布，意见截止 2026-11-30（公示页）`
- 好：`低压接入限值由 100kW 上调至 250kW，2027-01-01 生效`
- 坏：`发布了新版导则`、`有新的技术要求`

带上**版本号、生效或截止日期、以及变的那个数**。这三样是后面做判断唯一用得上的东西。

## 6. 汇报

优先说**有截止日期的事**——那是会过期的。其次说现行版本的变化。最后说采集状态异常的
对象。没有窗口临近时，明确说一句「近期没有截止日期」，比含糊带过有用。
