# 报告生成

报告是这套系统唯一的输出形态：材料进库、字段上板、最后变成一份能拿去做决定的东西。

一条底线：**报告里的每一句事实都要能追回到库里的一条材料。** 追不回的，要么删掉，
要么明写「无来源」。

## 1. 写之前

1. `search_knowledge` 把相关材料找齐，`read_knowledge` 读全文——**不要只凭检索片段写**，
   片段会把否定句、条件句的前提切掉。
2. `list_entities` / `read_entity` 取当前字段值与采集状态。
3. 检索不到的主题，记下来，报告里要单列。

## 2. 结构

固定四段，不要自创：

1. **结论**：三到五句，直接说。读者只看这一段也能做决定。
2. **依据**：每条结论对应的事实，逐条带来源。
3. **缺口**：没查到的、来源不可靠的、采集异常导致我们根本没在看的。
4. **建议动作**：具体到「配哪个源」「抓哪个链接」「找谁确认」，不要写「持续关注」。

第 3 段是这份报告最有价值的部分，**不要因为它不好看就省掉**。

## 3. 引用怎么写

每条事实后面跟一个来源标记，形式统一：

```
X-3000 额定功率 300kW〔条目：友商 B 2026 规格页〕
2026 版导则意见截止 2026-11-30〔条目：TSO-A 公示页 2026-09〕
```

要求：

- 指向**库里的条目**，不是凭记忆的网址。
- 同一句话里混了两个来源的事实，就拆成两句。
- 字段值来自看板时，写清是哪个对象的哪个字段，并说明它的证据链接。

## 4. 不确定怎么标

在正文里就地标注，不要都堆到末尾的免责声明里：

- **来源二手**：`（转述，未见原文）`
- **版本存疑**：`（2025 版，是否已被 2026 版代替未确认）`
- **口径不同**：`（对方按交流侧计，我方按直流侧计，不可直接比较）`
- **完全没有**：`该项无可用来源`

**禁止**用「据了解」「业内普遍」「预计」来填补空白。没有就是没有——这是用户定过的
规矩，报告里同样适用。

## 5. 数字

- 照抄原文的数字与单位，不要换算。需要换算时**两个都写**：`1.2 GW（= 1200 MW）`。
- 不同来源数字打架时，两个都列，写明各自来源，**不要取平均，也不要挑一个顺眼的**。
- 没有时间戳的数字要标出采集时间：`截至 2026-09-11 的页面`。

## 6. 交付

报告写好后用 `save_insight` 送到展示屏，标题写清主题与日期。
需要长期保留的，同时存一条知识条目，`doc_type` 写「报告」，
`entity` 填主要对象（跨多个对象时留空）。

## 7. 自检

1. 结论段里的每一句，在依据段里都有对应的事实吗？
2. 每条事实都有条目来源吗？
3. 缺口段是空的吗？——如果是，多半是你没写，而不是真的没有缺口。
4. 有没有出现「据了解」「预计」「业内普遍」？
5. 建议动作是具体的操作，还是「持续关注」？
