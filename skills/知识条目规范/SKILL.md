# 知识条目规范

知识库是**原始材料**，不是笔记本，也不是聊天记录的备份。库里每多一条无用条目，
检索时的信噪比就低一分，而检索变差是不可见的——它不报错，只是让人找不到东西。

下面的规则按「入库前先问自己」的顺序排列。

## 1. 什么值得入库

只有同时满足两条才入库：

1. **它是别人写的、可溯源的材料**——公告、规范、白皮书、论文、产品页、会议纪要原文。
2. **将来可能被检索**——你能说出一个具体的问题，它是答案的一部分。

以下**不入库**，一条也不要：

- 你自己的推理、总结、判断。这些是你当场说的话，不是材料。
- 对话里用户随口提到的事实，除非用户明确说「存下来」。
- 一整个网站的导航、目录页、只有标题没有正文的页面。
- 已经在库里的同一份材料的另一个副本。先 `search_knowledge` 查一遍。

**判据**：如果这条内容的唯一来源是你自己，它就不是知识，不要入库。

## 2. 一条条目切多大

一条 = **一份完整材料**，或**一份长材料中能独立回答问题的一节**。

- 一份 3 页的公告 → 一条。
- 一份 80 页的并网规范 → 按章节切，「第 4 章 电能质量要求」是一条。
- 一次会议的 12 条纪要 → 一条。不要切成 12 条，它们互相是上下文。

切分的检验办法：**把这一条单独拿给一个没读过原文的人，他能看懂这说的是什么吗？**
看不懂就切大了一号；里面明显掺着三个不相干的主题就切小一号。

上限是硬的：单条 64KB。超了就按章节切，不要靠删正文压进去。

## 3. 入库的三条路，用哪条

| 情况 | 用什么 | 会发生什么 |
|---|---|---|
| 手上有链接 | `ingest_url` | 抓正文、存条目、留原链接；**不存原件** |
| 用户贴了一段文字要你存 | `save_knowledge` | 直接入库，来源记 `conversation` |
| 用户拖了文件进来 | 界面已处理 | 不需要你做什么 |

`ingest_url` 的行为要记住：来源域名若在该对象**已登记的采集源**内，条目直接入库；
否则进**待采纳区**，用户在看板上点过才生效。这不是失败，是设计——被挡住时照实说
「已放入待采纳区」，不要重试，也不要改用 `save_knowledge` 把正文绕进去。**绕过闸门
就是把判断权从用户手里拿走。**

## 4. 标题怎么起

标题是检索结果里唯一先被看见的东西。

- 好：`TSO-A 2026 版并网导则 第 4 章 电能质量`、`友商 B 2026Q3 固件更新说明`
- 坏：`公告`、`网页内容`、`关于技术要求的文档`、`重要资料`

规则：**主体 + 时间/版本 + 具体内容**。没有时间信息就省掉时间，不要编。

## 5. 归属与文档类型

两个字段，主次分明：

- `entity`：**主索引**。这份材料是关于哪个跟踪对象的（友商 / 规则与准入方 / 客户）。
  先 `list_entities` 看名字，照抄，不要自己拼。
- `doc_type`：次分类。产品规格书 / 标准说明书 / 技术论文 / 公告 / 白皮书 等。

**拿不准归属就留空。** 空归属会被单独计数并显示出来，是可见的待办；胡乱归属则会
把一条材料藏进错误的对象里，再也找不到。**留空是诚实，猜是污染。**

## 6. 入库之后

- 入库不等于知识可用。要让看板上出现字段值，用 `extract_fields`，并遵守
  [证据规范]——引文必须在条目正文里逐字存在。
- 检索不到东西时，`search_knowledge` 会把这次查询记成缺口。**不要因为没检到就
  去编一个答案**，照实说库里没有，并说明可以抓哪个链接补上。

## 7. 自检清单

入库前，逐条回答：

1. 这是别人写的材料吗？（不是 → 不入库）
2. 库里有了吗？（有 → 不入库）
3. 标题说清了主体、时间、内容吗？
4. 归属对象是 `list_entities` 里真实存在的名字吗？拿不准是否留空了？
5. 内容是正文，不是导航、广告、版权声明吗？
