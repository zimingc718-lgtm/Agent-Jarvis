# AIDC 供电架构与电网 — 资料库

两份洞察报告的成品与其全部可取得的原始文献。

## 目录

| 目录 | 内容 |
|---|---|
| `01_报告/` | 两份报告的 PDF 成品与 HTML 源文件 |
| `02_原文_供电架构/` | 《AIDC 供电架构》引用的原始文献，文件名前缀 `P<编号>` |
| `03_原文_电网/` | 《AI 数据中心与电网》引用的原始文献，前缀 `G<编号>` |
| `04_文本层/` | 图片型 PDF 与需逐字核对的一手件的文本抽取；`_辅助_` 前缀为检索用中间件 |
| `清单.md` | 人读索引：编号 → 标题 → 本地文件 → 取回方式 |
| `清单.csv` | 同一索引的机器可读版（UTF-8 BOM，Excel 可直接打开） |

文件名中的编号与报告「来源清单」中的编号一致，可双向对照。

## 取回口径

- 共 227 条来源，取得原文 **214** 条，未取得 13 条。
- 未取得的条目**在报告中均已按实际层级标注**，没有任何一条被当作一手数值引用。
- 三类特殊取回方式见 `清单.md` 开头的说明。其中 opencompute.org 全站对爬取返回 403，
  OCP 规范原文是经互联网档案馆 `id_` 原始字节接口取回的。
- `04_文本层/` 中带编号的文件是**逐字核对过**的抽取结果；报告里所有标「逐字」「原文」的引文，
  都可以在对应文本层文件中检索到。

## 与治理基线的关系

本目录**不是受控交付物**，但 `tools/governance.py` 的 `discover_controlled_files`
扫描整个仓库根目录，只排除 `node_modules`、`.next*`、`.git` 等；`.pdf` 不在
`IGNORED_SUFFIXES` 中。因此：

> 新增本目录后，下一次 `python tools/governance.py verify` 会对这里的每个文件
> 报 `FAIL UNBASELINED_FILE`。

两种处理方式，按需要选一种：

1. **纳入基线** — 在 CR 分支上按 CLAUDE.md 第三节的顺序（先把 main 合进 CR 分支 →
   再 `snapshot` → 再合回 main）跑一次 snapshot。代价是 252 MB 进入哈希链与版本库。
2. **排除在基线之外** — 在 `tools/governance.py` 的 `IGNORED_REL_PREFIXES` 中加入
   `("资料库",)`，并在 `.gitignore` 中加 `资料库/`。这与既有的 `.claude/worktrees` 处理方式同构。

**方式 2 更合适**：本目录是研究素材而非受控产物，252 MB 的二进制文件进版本库
会让克隆和哈希校验都显著变慢；而 `IGNORED_REL_PREFIXES` 正是为「在仓库里但不该受控」
这类目录准备的机制。但这属于改动治理工具的边界，**未经确认不自行改动** —— 本次只放文件，
两处改动都没有做。
